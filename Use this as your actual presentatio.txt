Main Demo: Reliable End-to-End Flow
This is the safest primary demo. Use the manual trigger first.

In Protocol Zero, trigger a manual incident
service: cartservice
incident type: pod_restart_loop
severity: critical
click Trigger and Process
What to say while it runs:

“I’m triggering a realistic incident.”
“Protocol Zero is now creating a normalized incident object.”
“The investigation, developer, and devops agents run in parallel.”
“Their findings are correlated into a likely hypothesis.”
“A safety layer checks whether remediation should be proposed or executed.”
“Because this demo is in dry-run mode, it will simulate the action instead of making a destructive production change.”
Open the created incident from the timeline
Show these fields in the detail JSON:

What to say:

How To Prove It’s Real
After showing the incident detail, show the generated artifacts on disk.

Get-ChildItem .\post_mortems

If you want to open one:

Get-Content .\docs\codefixes\<incident-id>.md

“The system doesn’t just display UI state. It persists the incident and writes concrete artifacts for handoff and review.”
Optional Advanced Demo: Real Fault Injection
If time allows, do this after the manual flow, not before.

Inject a real fault
.\scripts\chaos.ps1 -Action kill-pod -Service cartservice
Then trigger detection
Invoke-RestMethod -Uri "http://localhost:8000/api/incidents/detect?auto_process=true" -Method POST
What to say:

“Now I’m creating a real cluster fault.”
“Protocol Zero is detecting from observability rather than a manual trigger.”
“The rest of the workflow is the same: investigation, reasoning, remediation planning, and reporting.”

If Something Goes Wrong
If Prometheus looks empty:

run up
say: “Prometheus starts with an empty query screen by default.”
If Grafana looks empty:

refresh the Protocol Zero Demo dashboard
rerun:
.\scripts\provision_grafana_demo_dashboard.ps1
If Protocol Zero dashboard is empty:

trigger the manual incident first
refresh the page
